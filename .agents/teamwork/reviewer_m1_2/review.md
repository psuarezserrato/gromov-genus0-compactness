   Training or few-shot prompting a 9B model on these examples teaches the model self-referential circular logic (`exact my_goal`) rather than constructive mathematical proofs. Furthermore, regex parsing errors in `harvest_test_proofs` extracted informal docstring phrases as spurious theorem declarations named `with` and `in`.

## Detailed Findings

### [Major] Finding 1: Strict 9B Model Policy CLI Bypass & Unhandled 404s

- **What**: In `tools/ollama_lean4_client.py`, lines 936–947 (`cmd_query`), 990–1001 (`cmd_autoformalize`), and 1042–1053 (`cmd_suggest_tactic`), model resolution is guarded by:
  ```python
  model = args.model
  if not model and not args.dry_run:
      model, reason, _ = detect_best_model(args.host, preferred_tag=args.model)
      if not model:
          ...
          return 1
  else:
      model = model or "gemma2:9b"
  ```
- **Where**: `tools/ollama_lean4_client.py`, lines 936–947, 990–1001, 1042–1053, and `query_ollama` (lines 620–645).
- **Why**: 
  1. If `--model` is supplied by the user or an automated script (e.g. `--model gemma4:12B` or `--model gemma2:27b`), `not model` evaluates to `False`. The code falls through to `else: model = model or "gemma2:9b"`, completely bypassing `detect_best_model`.
  2. Inside `query_ollama`, there is zero enforcement of `is_allowed_9b_model(model)` or `ACTIVE_CONFIG["enforce_9b_policy"]`.
  3. Host inspection reveals that `gemma4:12B` (ID `4eb23ef187e2`, 7.6 GB) is actively installed in the local Ollama repository. Passing `--model gemma4:12B` executes the 12B model on the user's unified RAM, violating COMPLETION_PLAN §5.1.
  4. Inspection of `.agents/gemma_usage.jsonl` lines 12 and 16 reveals unhandled `HTTP Error 404: Not Found` errors generated for `gemma2:27b`, showing that the client previously dispatched requests for uninstalled forbidden models directly to Ollama.
  5. The client self-test (`Test 3a`) only tested `detect_best_model` in isolation with mock dictionaries, failing to detect that the CLI dispatch entrypoints bypass `detect_best_model`.
- **Suggested Fix**:
  1. In `query_ollama`, enforce:
     ```python
     if ACTIVE_CONFIG.get("enforce_9b_policy", True) and not is_allowed_9b_model(model):
         print(f"[WARNING] Model '{model}' violates 9B policy. Redirecting to 9B cascade.", file=sys.stderr)
         model = MODEL_PRIORITY_CASCADE[0]
     ```
  2. In `cmd_query`, `cmd_autoformalize`, and `cmd_suggest_tactic`, always call `detect_best_model(args.host, preferred_tag=args.model)` regardless of whether `args.model` is `None` or whether `args.dry_run` is set.

### [Major] Finding 2: Facade / Circular Dummy Proofs in `data/gemma_accepted_proofs.jsonl`

- **What**: 344 records (46.0% of the 748 library declarations, and 26.7% of all records) contain dummy proofs generated by line 167 of `tools/build_accepted_proofs_dataset.py`:
  ```lean
  by
    -- Proved declaration in <module>
    exact <declaration_name>
  ```
- **Where**: `tools/build_accepted_proofs_dataset.py:165-168` and `data/gemma_accepted_proofs.jsonl`.
- **Why**: 
  1. `tools/extract_accepted_proofs.lean` selects all declarations in `env.constants` where `ci` is `.thmInfo`. In Lean 4, structure field projections (e.g. `AuditRecord.manifold_with_corners_available`, `MarkedStableTreeLimit.mark_ne_node`, `VaryingAlmostComplexStructures.J_seq_sq`), equational lemmas (`is_principal_component.eq_1`), inductive theorems (`ConcentrationData.mk.sizeOf_spec`, `NeckDegenerationData.mk.injEq`), and internal subproofs (`inv_lin.proof_3`, `CoreSmoothLocalConvergesOn.proof_1`) are registered as `.thmInfo`.
  2. Because these declarations do not possess standalone `theorem ... := by ...` blocks in source files, `slice_source_proof` failed to extract a proof body.
  3. Instead of filtering out non-human theorem declarations or extracting genuine proofs, `build_accepted_proofs_dataset.py` synthesized a circular dummy proof: `by exact <self_name>`.
  4. Training an LLM on prompts where the proof of `T` is `exact T` teaches the model self-referential tautologies, undermining the autoformalization proving loop.
- **Suggested Fix**:
  1. In `tools/extract_accepted_proofs.lean`, filter out auxiliary compiler-generated lemmas (e.g. names ending with `.injEq`, `.sizeOf_spec`, `.eq_*`, `.proof_*`).
  2. In `tools/build_accepted_proofs_dataset.py`, discard any record where a genuine proof body cannot be extracted from source code. Do NOT emit fallback `exact <self>` records.

### [Major] Finding 3: Docstring Contamination and Spurious Declarations in `harvest_test_proofs`

- **What**: The regular expression in `tools/build_accepted_proofs_dataset.py` (lines 75–78) matches occurrences of the English word "theorem" inside docstrings and comments, producing malformed records.
- **Where**: `tools/build_accepted_proofs_dataset.py:75-78` and `data/gemma_accepted_proofs.jsonl`.
- **Evidence**:
  - `tests.ChallengeMilestone3Bootstrap.with`: extracted from docstring text `theorem with ZERO sorry...`, named `with`.
  - `tests.ChallengePhase3ModelB.in`: extracted from docstring text `theorem in GhostBranching.lean...`, named `in`.
  - `tests.ChallengePhase3StressCases.in`: extracted from docstring text `theorem in the bubbling or compactness pipeline...`, named `in`.
- **Why**: Unescaped regex search across multiline files without comment stripping treats comment prose containing "theorem" as declaration headers.
- **Suggested Fix**: Strip block comments (`/- ... -/`) and single-line comments (`-- ...`) before regex extraction, or anchor `theorem`/`lemma` to line start.

### [Minor] Finding 4: Empty Scope Silent Pass in `PhaseAxiomCensus.lean`

- **What**: When `./tools/phase_axiom_census.sh` is passed an invalid, misspelled, or non-existent module prefix (e.g. `./tools/phase_axiom_census.sh GromovCompactness.NonExistent`), it reports:
  ```
  Total declarations in scope: 0 (theorems: 0)
  Clean declarations: 0 (theorems: 0)
  Sorry-dependent: 0 (theorems: 0)
  STATUS: CLEAN (0 sorryAx dependencies)
  ```
  and exits with code 0.
- **Where**: `tests/PhaseAxiomCensus.lean:107-111`.
- **Why**: The status check is `dirty.isEmpty && nonstandard.isEmpty`. If 0 declarations match the prefix, `dirty` is empty, so it reports CLEAN and exits with code 0. A typo in a module name in CI or scripts would silently pass.
- **Suggested Fix**: Add a check: if `clean + dirty.size == 0`, throw an error or exit non-zero:
  `throwError m!"Phase axiom census error: 0 declarations found for scope '{targetPrefix}'. Check module name spelling."`

---

### [Minor] Finding 5: BM25 Tokenizer Ignores Unicode Mathematical Symbols

- **What**: `tokenize_lean_identifier` in `tools/premise_retrieval.py` filters via `[A-Za-z0-9]+` and drops all non-alphanumeric characters.
- **Where**: `tools/premise_retrieval.py:32-39`.
- **Why**: Mathematical queries containing Lean 4 Unicode operators (e.g., `∂`, `∫`, `ω`, `Σ`, `ℂ`, `ℝ`, `λ`, `ε`) have those symbols discarded. For example, `r.retrieve("∂ f / ∂ z = 0")` yields 0 tokens and returns `[]`.
- **Suggested Fix**: Map common Lean 4 Unicode math symbols to text tokens (`∂` -> `cauchyriemann` / `deriv`, `∫` -> `integral`, `ω` -> `omega`, `ℂ` -> `complex`, `ℝ` -> `real`) before regex tokenization.
